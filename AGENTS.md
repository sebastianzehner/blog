# Blog — Agent Instructions

This file is read by Pi (and other agent harnesses) when operating in this directory.
It supplements the global `AGENTS.md` with project-specific conventions.

## Project Overview

- **Type:** Hugo static site, multi-language blog
- **Theme:** [Blowfish](https://blowfish.page/) with Catppuccin color scheme
- **Domain:** `sebastianzehner.com` (hosted on Netlify)
- **Hugo Version:** 0.163.3 (extended)
- **Languages:** German (primary), English, Spanish

## Content Structure

### Post Directory Layout

Each post lives in its own directory under `content/posts/<slug>/`:

```bash
content/posts/my-post-slug/
├── index.de.md   # German (primary)
├── index.en.md   # English
└── index.es.md   # Spanish
```

- The **slug** (directory name) is always English, lowercase, kebab-case
- Files are named `index.<lang>.md` — Hugo resolves language from the file extension
- Always create all three language versions; never publish a single-language post

### Frontmatter

Every post uses **TOML** frontmatter (delimited by `+++`). This is consistent
across the entire Hugo setup — all config files and existing posts use TOML.
Never use YAML for frontmatter in this project.

```toml
+++
title = 'Article Title'
description = 'SEO meta description, 150–160 characters'
summary = 'Short excerpt shown on the post list and homepage'
date = 2026-07-29T12:00:00-03:00
lastmod = 2026-07-29T12:00:00-03:00

tags = ['Tag1', 'Tag2', 'Tag3']
categories = ['TechLab']

[params]
showComments = true
chatId = 'unique-slug-for-comments'
+++
```

- **`title`**: Article heading displayed in the browser and on the post page
- **`description`**: Used for SEO meta tag (Open Graph, Twitter cards)
- **`summary`**: Shown in post lists and homepage card view
- **`date`**: Publication date; timezone `-03:00` (Paraguay)
- **`lastmod`**: Always update when revising the post
- **`tags`**: 3–6 relevant tags, selected **only** from the predefined list in `config/tags.yaml`
- **`categories`**: One of three fixed categories — `TechLab`, `Paraguay`, or `Roadtrip`
- **`showComments`**: `true` for all published posts (Cactus Comments backend)
- **`chatId`**: Unique per post, kebab-case, used by the Cactus Comments backend
  (Matrix rooms). Must be **identical across all three language versions** of
  the same post. Can be reused for posts on the same topic to avoid creating too
  many Matrix rooms.

## Writing Conventions

### Language Rules

| Context                | Language                         |
| ---------------------- | -------------------------------- |
| Blog post content      | Matches file language (DE/EN/ES) |
| Code & code comments   | English                          |
| Git commit messages    | English                          |
| Post slugs (URL paths) | English, kebab-case              |
| Frontmatter keys       | English (Hugo standard)          |

### Tone

- First-person perspective (`ich` / `I` / `yo`)
- Technical but accessible — assume reader knows Linux basics
- No filler introductions; start with the hook
- End with a personal sign-off (DE: `Liebe Grüße / Sebastian`, EN: `Best
regards, / Sebastian`, ES: `Un saludo, / Sebastian`)

### Content Guidelines

- Keep paragraphs short (3–4 sentences max for web readability)
- Use H2/H3 subheadings every 200–300 words
- Active voice preferred
- Link to external resources where helpful (official docs, project repositories,
  references)
- Code blocks always specify language (bash, toml, properties, etc.)

### Target Word Count

Aim for **~1,200 words** per article as a baseline. Adjust based on topic
complexity — tutorials may run longer (1,500–2,000), opinion pieces shorter
(800–1,000). The goal is substance without fluff.

### SEO Guidelines

- **Primary keyword** in: title, first paragraph, at least one H2, and the
  `description` field
- **Description** (meta): 150–160 characters; front-load keyword + reader
  benefit within the first 120 characters for mobile visibility
- **Summary**: Short excerpt shown on the post list; 1–2 sentences, no keyword stuffing
- **Semantic keywords**: Use related terms naturally in body text (no stuffing)
- **Internal linking**: Link to related posts on the blog where relevant
- **External links**: Link to authoritative sources (official docs, project
  repositories, relevant references)
- **Alt text for images**: Descriptive, includes keyword where natural
- **URL slug**: Short, descriptive, kebab-case, include primary keyword if possible
- **No keyword stuffing**: Primary keyword appears where it fits naturally —
  no fixed frequency target

### Image Conventions

- **Featured image**: Created via `config/create-blog-cover.sh` (see below)
- **Filename**: `featured.webp`, placed in the post directory alongside
  `index.*.md` files
- **Dimensions**: 1280×720 (16:9), generated by ImageMagick
- **Colors**: Catppuccin Mocha — BG `#181825` (Mantle), Text1 `#89b4fa`
  (Blue), Text2 `#cba6f7` (Mauve)
- **Font**: CaskaydiaCove Nerd Font Mono, 120pt
- **Usage**: Hugo automatically picks up `featured.webp` as the post's featured
  image
- **Additional images**: Place in the post directory with descriptive
  lowercase-kebab-case names
- **Format**: Prefer WebP for web delivery; Hugo can convert if needed

### Creating a Featured Image

```bash
config/create-blog-cover.sh
```

The script prompts for two title lines and generates a `featured.webp` in the
current directory. Run it from the post directory:

```bash
cd content/posts/my-post-slug
../../config/create-blog-cover.sh
```

Output defaults to `<title1>-<title2>-cover.webp` — rename to `featured.webp`
for Hugo auto-detection.

## Build & Deploy

```bash
hugo --minify           # Build production site
hugo server             # Local preview (default port 1313)
hugo server -D          # Include drafts
```

- Site is deployed via **Netlify** (see `netlify.toml`)
- Hugo version pinned to `0.163.3` extended in Netlify config
- `public/` is the build output — never edit directly

```bash

```

- Typical commit types:
  - `content: add post about X`
  - `content: update post X translation`

  - `chore: update hugo.toml`

## Local Preview

When asked to preview the blog, start Hugo in a detached tmux session:

```bash
tmux new-session -d -s hugo-preview "hugo server --baseURL http://localhost:1313"
```

Then open it in the browser:

```bash
brave "http://localhost:1313"
```

To check the preview status:

```bash
tmux list-sessions
```

If `hugo-preview` is listed, the preview is running. If not, offer to start it.

To stop the preview:

```bash
tmux send-keys -t hugo-preview C-c
tmux kill-session -t hugo-preview
```
